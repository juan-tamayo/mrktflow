# Module: themes-content

Objective: extensible design and everyday content editing without coupling presentation to commerce internals. Depends on platform, identity and catalog. Inherits [template contracts](docs/template-contracts.md), [architecture](docs/architecture.md), and [commands](docs/coding-handoff.md).

## Requirements

- **THEME-01:** Ship a complete responsive default theme and a documented developer-theme format supporting PHP/Blade, HTML, CSS and compiled Vue. Compatibility and asset checks run before activation.
- **THEME-02:** Page/article/menu editor supports typed sections, ordering, visibility and style tokens. Merchant can assign templates to pages, categories and products, with fallback defaults.
- **THEME-03:** Separate draft/published revisions, authenticated previews, optimistic editor locking, explicit publish and rollback. Editing drafts does not alter live pages.
- **THEME-04:** Admin imports data-only template packages with staging, validation, media/reference mapping and a reviewable report. No raw executable source upload in admin. Developer code packages use the separate trusted installation workflow.
- **THEME-05:** Navigation links, slugs, reserved paths, metadata, canonical URLs and redirect loops are validated. Public sitemap excludes drafts, private pages, cart, checkout and account routes.
- **THEME-06:** Theme activation is reversible and preserves content. Detect unavailable section types/template keys and require a mapping or fallback; never discard incompatible settings silently.
- **THEME-07:** Typed theme extension slots include offer banners, signup forms, stock/countdown signals, purchase aggregates, verified reviews, referral calls to action and hub product groups. Core supplies eligibility/facts; themes receive no contact/order data or authority to invent stock, prices or ratings.

## Verification

Test malicious archives/HTML/URLs, wrong manifest versions, unavailable sections, conflicting edits, failed activation, rollback and draft cache leakage. Target `php artisan test --filter=ThemesContent`; browser editor/publish/rollback flow. Success: add a category guide and custom product presentation without editing core commerce code.

T061 implements the THEME-01 registry slice: `PlatformVersion` (core `1.0.0`, theme API `1`) is the version source manifests are checked against, and `RegisterTheme` validates installed manifests — structure, core/theme-API ranges, confined template/asset paths, referenced files present — recording an explicit `valid`/`invalid` status with reasons in `installed_themes` before any activation exists; only a valid registration is activatable, and activation remains T068 (`bin/php artisan test --filter=ThemesContentRegistry`).

T063 implements the THEME-02 section-registry slice: the twelve built-in blocks (hero, rich-text, image-text, gallery, category-grid, product-grid, featured-product, specifications, comparison-link, faq, call-to-action, article-list) are declared as data in `themes/default/sections/definitions.json` — typed settings fields with constraints, a binding spec and a per-page repeat limit each — and parsed strictly by `SectionRegistry`. `ValidateSections` validates section payloads against the registry: unknown block types, unknown fields and every constraint violation reject with errors naming the section, field and problem; bindings resolve only through the catalog read model (draft and nonexistent references fail with one indistinguishable message) and validated output carries resolved public summaries. `RenderSections` renders validated sections through the theme's `sections` view, composed into a page through T062's `ComposePage` slot assignment, so platform/unknown slot targets refuse composition. The section editor remains T064 and article records T065 (`bin/php artisan test --filter=ThemesContentSection`).

T064 implements the THEME-02/WEB-06 editor slice: one working section draft per (page, slot) in `content_drafts`, with targets derived from the T062 slot contract (theme slots in the announcement/main regions; platform slots and unknown pages refused). `SaveSectionDraft` validates through `ValidateSections` before persisting — invalid payloads write nothing — stores the normalized payload with binding references only, increments an optimistic-lock version (a stale save conflicts with the current state, never overwrites), and audits each save; a rejected save returns the validator's errors grouped per section plus document-level errors so the editor recovers without losing work. The Vue editor at `/admin/content-editor` (read under `content.read`, save under `content.write`, both server-enforced) generates settings forms from the registry's typed definitions, adds only registry blocks within their repeat limits, reorders by keyboard (native move controls and Alt + arrow keys, focus following the moved section, `role="status"` announcements), and previews the draft as the real server-rendered sections fragment from `RenderSections` at desktop/mobile widths — preview persists nothing. Revisions/publication remain T067 (`bin/php artisan test --filter=ThemesContentEditor`).

T065 implements the THEME-02/THEME-05 records slice: `SaveContent` creates page, article and menu rows with unique kebab slugs and reserved-aware public paths (`pages/{slug}`, `journal/{slug}`). Slugs cannot reuse reserved storefront/system first segments or an existing category-tree path. Menu item URLs must be local paths; administration, installer and remote URLs are refused and persist nothing. The article-list section reads published articles through `ListArticles` and keeps its empty copy when none exist. Staff manage records at `/admin/content` (`content.read` to view, `content.write` to save). Revisions, public page/article routes and sitemap exclusion remain later tasks (`bin/php artisan test --filter=ThemesContentPage`).

T066 implements the THEME-02 visual-assignment slice: `AssignLayout` stores one `layout_assignments` row per product, category or page — a template key only, never a copied price or attribute payload. Product schemas keep their `default_template_key` as a fallback until a product assignment exists; switching layout does not rewrite schema versions, typed attributes, variant amounts or quote totals. Category landing templates bind live catalog products through `CatalogReader` at render time. `ComposePage` records the assigned content view on product and category pages. Staff with `content.write` assign templates at `/admin/layouts` from the product, category and page pickers; privileged staff still pass 2FA. `GET /` stays HTTP 503 (`bin/php artisan test --filter=ThemesContentAssignment`).

T067 implements the THEME-03 revision/publication slice: every page, article and section-draft save appends an immutable `content_revisions` snapshot and advances only the draft pointer. Creating a record with status `published` may set the first live pointer; later saves never move it. `PublishContent` (`content.publish`) re-validates the current draft (section drafts through `ValidateSections`) and atomically switches `published_revision` under an optimistic version lock — a stale expected version conflicts and live content stays put. `ListArticles` and `ReadPublishedContent` read the published snapshot, not the working row. Authorized staff preview drafts at `/admin/preview/pages/{id}`, `/admin/preview/articles/{id}` and `/admin/preview/sections` (`content.read`, noindex, no-store); preview never publishes. `GET /` stays HTTP 503. Rollback and theme activation are T068 (`bin/php artisan test --filter=ThemesContentPublish`).

T068 implements THEME-03 rollback and THEME-06 activation: `RestoreRevision` copies an earlier immutable snapshot into a new draft revision and publishes that new revision under the same optimistic version lock — historical rows stay put. `ActivateTheme` consults `ThemeRegistry::isActivatable`, then refuses themes that miss SystemSlots route templates or that would leave live section types or assigned visual keys unmapped; a mapping that cannot re-validate without dropping settings is refused. Failure writes no `theme_activations` row, so the previous active theme remains. Live documents are not rewritten. Staff with `content.read` open `/admin/themes`; activation and restore require `content.publish`. Privileged staff still pass 2FA. `GET /` stays HTTP 503 (`bin/php artisan test --filter=ThemesContentActivation`).

T069 implements THEME-04 merchant template import: `ValidateImport` stages a ZIP to private storage, enforces archive/size/MIME/path rules, and rejects PHP, Vue, script payloads and unknown blocks before a row is kept. `ApplyImport` maps `ref:` catalog aliases and package media onto published public images, then writes only section drafts through `SaveSectionDraft` — published pointers never move. Replaying the same import intent is a no-op. Staff with `content.read` open `/admin/content/import`; staging and apply require `content.write`. Privileged staff still pass 2FA. `GET /` stays HTTP 503 (`bin/php artisan test --filter=ThemesContentImport`).

T070 implements THEME-05/WEB-05 public SEO: published pages and articles render at `/pages/{slug}` and `/journal/{slug}` from the live revision only. Slug changes record `content_redirects` through `SaveRedirect`, which collapses chains and refuses loops or private destinations (`/cart`, `/checkout`, `/account`). The public sitemap excludes drafts, private routes and the closed homepage. Preview remains noindex/no-store. `GET /` stays HTTP 503 (`bin/php artisan test --filter=StorefrontSeo`).

T071 implements THEME-01/THEME-04 developer tooling: `theme:validate` registers a reviewed Blade/CSS/Vue package from `themes/` (the shipped fixture is `themes/example`) with an explicit `trusted-developer-code` trust level, no sandbox, and admin executable upload refused. Vite compiles theme.json asset entries without editing commerce core. Validation does not activate the theme or open `GET /` (`bin/php artisan test --filter=ThemesContentDeveloper`).
